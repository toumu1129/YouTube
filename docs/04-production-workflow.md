# 制作フロー

1本あたり **30〜45分** で回せる状態を目標にする。
1日1本なら、週末に7本まとめて作る（バッチ制作）ほうが早い。

---

## 全体の流れ

```
① ネタ選ぶ      backlog.md から1つ
② 裏を取る      出典2つ以上（→ 06-fact-checking.md）
③ 台本を書く    _template.md をコピーして埋める     15分
④ 音声を作る    AI音声 or 自分で録音               5分
⑤ 素材を集める  ライセンス確認済みの映像           10分
⑥ 編集する      テロップ＋カット                   15分
⑦ 投稿する      → 05-publishing-checklist.md        5分
```

---

## Claudeとの共同作業フロー（合意済み・固定）

Claude Codeが1本を作るときの、ユーザーとの役割分担はこの順で固定する。
**毎回この順を守ること。** 台本を書く前に映像を作らない、映像ができる前にタイトルを送らない。

```
① ユーザー「次の動画案を見せて」→ Claudeが候補を提示
② ユーザーが候補から1本選ぶ
③ Claudeが台本の中身を確認する。修正が必要なら文面を整える
   （読み指定・文字数・出典の未確認項目もここで洗い出す）
④ Claudeが台本に合った動画を作る
   - フリー素材は基本Claudeが探す
   - ふさわしい写真・動画が見つからなければ、無理に妥協せず
     「いい素材が見つからない」と正直に伝える。ユーザーが探す
⑤ Claudeが2点を生成してユーザーに渡す
   - 映像とナレーションを合わせたファイル（sXXX-with-audio.mp4。テロップは入れない）
   - テロップ用ファイル（sXXX-narration.srt。句読点なし、実測タイミング）
⑥ Claudeがテロップの編集案（強調語・色・配置）をテキストで送る
   同時にタイトル案・概要欄の文章も送る
⑦ ユーザーがCapCut側で映像とテロップを組み合わせる（Claudeはここをやらない）
```

台本修正・音声再生成・SRT再生成・build.py再実行は1セットで、
台本の文言を直すたびに毎回全部やり直す（音声だけ直してSRTを放置、のような
片手落ちはs020の事故の再発になる。[⑥ 編集](#⑥-編集)の節を参照）。

## ④ 音声 — 決定：AI音声（VOICEVOX 青山龍星）

| 選択肢 | 費用 | 商用可 | 備考 |
|---|---|---|---|
| **VOICEVOX（青山龍星）** | 0円 | 可（利用規約の範囲内） | **採用（s004以降）**。API経由で自動生成できる。クレジット表記が必要 |
| ElevenLabs（vidIQ経由） | 有料（クレジット制） | 可 | s020のみ採用。日本語は自然だが、vidIQのクレジットが頻繁に枯渇し量産に向かないため乗り換えた |
| CoeFont | 有料 | 可 | 検討したが未採用 |
| 自分で録音 | 0円 | — | 差別化力は最大だが、今回は不採用 |

> ⚠️ VOICEVOXは「競合と同質化する」という理由で一度不採用にしたが、
> ElevenLabs（vidIQ経由）のクレジット制約が量産のボトルネックになったため再検討し、採用に変更した。
> 差別化は声ではなく題材・出典で担保する方針（[8. ナレーション](01-channel-concept.md) 参照）。
>
> **クレジット表記必須。** 概要欄に「VOICEVOX:青山龍星」を入れること（VOICEVOX利用規約）。
>
> **生成方法：** `tools/gen_narration.py <台本.md>` で台本の「# 台本」表と「# 読み指定」表から
> 音声(`sXXX-narration.wav`)を自動生成する。VOICEVOXエンジンを `http://127.0.0.1:50021` で
> 起動しておく必要がある（このコンテナでは使い捨てなので、セッションのたびに
> `/root/voicevox_engine/linux-cpu-x64/run --host 127.0.0.1 --port 50021` で再起動する。
> エンジン本体が無ければ VOICEVOX/voicevox_engine の GitHub Release から
> `voicevox_engine-linux-cpu-x64-<version>.7z.001` を取得して展開する）。
> 生成後は `tools/make_srt.py sXXX-narration.wav sXXX-narration.txt` で字幕も実測から作る。

### AI音声で読ませるときの台本の書きかた

AI音声は「読み間違い」と「間の欠落」で一気に安っぽくなる。

**読みは台本の表記では直さない。** テロップはナレーションの文字列をそのまま出すので、
読ませたいからといってひらがなに開くと、画面までひらがなになってしまう。
**読みは各台本の「読み指定」欄に書き、`tools/gen_narration.py` が読み指定の表記→読みを
TTSに渡すテキストだけに置換して当てる。**（表の読み仮名に読点や空白を含めると、
VOICEVOXはそこで発話が途切れるので入れないこと。）

台本の文面で気をつけるのは、間のつくりかただけ。

- **句点で必ず区切る。** 長い一文はAI音声だと棒読みになる。5ブロックごとに文を切る
- **③の答えの直前に句点＋改行を置く。** そこに0.3秒の間ができ、聞き手が身構える
- **同表記異音の動詞に注意する。** 「止める」（とめる／やめる）、「入る」（はいる／いる）など、
  誤読すると**意味が反転する**語。読み指定に必ず書く。
  書きかえたほうが早いと判断したら、台本の文自体を変えてもよい

### 読み指定欄の回しかた

1. 台本の「読み指定」欄を見ながら、エンジン側で読みを当てる
2. **生成した音声は必ず一度通しで聞く。** 読み間違いは必ず起きる
3. 新しく見つかった誤読を**その台本の読み指定欄に追記する**
4. 他の回にも出てくる語なら、その台本にも書き写す

3と4をやるかどうかで、20本目以降の速さが変わる。**毎回ゼロから直すことになるかどうかの分岐点。**

### 設定の目安

| 項目 | 設定 |
|---|---|
| 声 | 落ち着いた低めの声を1つ決めて、**全本で固定する**（変えると別チャンネルに聞こえる） |
| 速度 | 標準の1.0〜1.05倍。AI音声は速くすると一気に聞き取れなくなる |
| 尺 | **書き出したら必ず秒数を見る。** 30秒を超えたら速度ではなく**台本を削って**直す |
| 感情・抑揚 | 低め。淡々と読ませるほうが「内容で引っぱる」設計に合う |
| 書き出し | WAV。MP3を再エンコードすると編集で音が痩せる |

### 収録の運用

- **7本ぶんまとめて生成する。** 設定のぶれを防げる
- 生成した音声は必ず**一度通しで聞く**。読み間違いは必ず起きる
- 読み間違いが出た語は、台本ファイルの末尾に「読み指定」として記録し、次回以降そのまま使う

## ⑤ 映像素材

**原則：出どころが説明できない素材は使わない。**
競合大手は転載で回しているが、同じことをすると収益化停止のリスクを抱え続ける。

| 手段 | 費用 | 注意 |
|---|---|---|
| **自分で撮る** | 0円 | カラス・スズメ・アリ・ダンゴムシは自力で撮れる。**最優先** |
| Pexels / Pixabay | 0円 | ライセンスは動画ごとに確認。まとめてDLせず1本ずつ見る |
| Getty / Adobe Stock | 有料 | 深海・大型動物など自分で撮れないもの用 |
| 国立公園・研究機関の公開素材 | 0円 | 利用条件を必ず読む。出典表記が必要なことが多い |
| 自作イラスト・図解 | 0円 | **実は一番強い。** 仕組みの説明は実写より図のほうが伝わる |

**素材の記録を必ず残す。** 各台本ファイルの「素材」欄に、URL・ライセンス名・取得日を書く。
あとで権利者から連絡が来たときに即答できる状態にしておく。

## ⑥ 編集

| ツール | 費用 | 向き |
|---|---|---|
| CapCut | 無料 | テロップの自動生成が速い。最初はこれで十分 |
| DaVinci Resolve | 無料 | 色と音を詰めたくなったら |
| Premiere Pro | 有料 | 既に慣れているなら |

**テンプレートを1回作って使い回す。** テロップの書体・位置・色を毎回決めていると時間が溶ける。

### テロップの当てかた

テロップはナレーション全文。**手打ちも、自動字幕の文字起こしもしない。**
台本の文字列をそのまま使い、タイミングだけ音声から実測する。

```
python3 tools/make_srt.py <音声.mp3> <台本テキスト> <出力.srt>
```

1. 上のコマンドで SRT を作る（無音を検出して発話区間を拾い、句読点で割った文節に対応させる）
2. **「発話区間 N = 文節 N」と出たか確認する。** 合わないときは字数比の按分に落ちるので手直しが要る
3. 改行位置を目で確認する（形態素解析は入れていないので、たまに惜しい位置で折れる）
4. CapCut の「字幕 → 字幕をインポート」で読み込む
5. 位置・書体・フチを当て、**「強調語」列**の語だけアクセント黄にする

**自動字幕を使わない理由：** AI音声の読みを文字起こしすると、台本にない表記ゆれが入る。
テロップはナレーション全文と一字一句同じであるべきなので、台本側を正とする。

### 画像の切り替え秒数も、必ず同じSRTから出す

**「台本の見積もり秒数（0:00-0:03 / 0:03-0:07 / …）」で画像の尺を決めてはいけない。**
それは収録前の設計図であって、実際にAI音声が読んだ長さではない。

s020で、まさにこれが原因の事故が起きた。字幕だけ実測（`make_srt.py`）に直し、
映像の切り替えを見積もり比例配分のまま放置したため、③→④の境界が3.76秒ずれ、
「まだ前の絵なのに次の話をしている」状態になった（詳細は
[`assets/s020/README.md`](../assets/s020/README.md)）。

**やること：** 画像編集用のスクリプト（`assets/sNNN/build.py`）は、
どのカードからどのカードまでを画像1枚に割り当てるかだけを持たせ、
**実際の秒数は毎回 `sNNN.srt` を読んで計算する。** 数字を決め打ちしない。
音声を作り直したら、`make_srt.py` → `build.py` の順に**両方を作り直す**。
片方だけ直すと、字幕・映像・音声のうち必ずどれかがずれる。

編集で必ずやること：
- [ ] 無音の間を全部詰める（0.2秒でも消す）
- [ ] 縦 1080×1920 で書き出す
- [ ] 下20%にテロップがはみ出していないか確認
- [ ] 音量ピークを -3dB 以下に
- [ ] **音を消して1回通して見る**。テロップだけで意味が通るか
- [ ] テロップがナレーションを**先出ししていない**か（答えが先に見えていないか）

## バッチ制作の組みかた

同じ作業をまとめると速い。1日で7本作るならこの順で。

```
午前  ネタ7本ぶんの裏取り        60分
午前  台本7本を続けて書く        90分
午後  AI音声7本を一気に生成＋検聴 30分  ← 設定のぶれを防ぐ
午後  素材を7本ぶん集める        60分
午後  編集7本                    105分
夕方  予約投稿7本を設定          30分
```

**音声生成はまとめてやる。** 日を分けると設定を変えてしまいがちで、チャンネルの統一感が落ちる。
声とパラメータは一度決めたら**紙に書いて固定する**こと。
