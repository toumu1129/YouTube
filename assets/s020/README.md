# s020 素材

画像のみの動画（音声・テロップなし）を組んだときの素材一式。

| ファイル | 用途 | 秒 | 出どころ |
|---|---|---:|---|
| `f1.jpg` | 牛 | 2.88 | Pexels / Ninety Seven Years（**クレジット必須**） |
| `f2.jpg` | 牛用磁石 | 3.84 | 生成AI（ChatGPT）／プロンプトは `image-prompts.md` |
| `f3.jpg` | 草ごと金属を飲み込む | 12.48 | 同上 |
| `f4.jpg` | 第二胃に磁石が留まる | 6.72 | 同上 |
| `f5.jpg` | 牛の顔アップ（真正面） | 2.88 | Pexels / celal keser（**クレジット必須**） |

## 組み立て

```
python3 build.py     # → s020.mp4
```

出力：1080×1920 / 30fps / 28.76秒 / 音声なし

### カットの秒数は `s020.srt` から自動で決まる（手で数字を打たない）

`build.py` は `IMAGE_CARDS`（どの画像が SRT の何枚目〜何枚目のカードに対応するか）
だけを持ち、実際の切り替え秒数は **毎回 `s020.srt` を読んで逆算する**。

```python
IMAGE_CARDS = [
    ("f1.jpg", 1, 1,   False),  # ①牛は、磁石を飲みます。
    ("f2.jpg", 2, 3,   False),  # ②冗談ではありません。専用の磁石が売られています。
    ("f3.jpg", 4, 6,   True),   # ③牛は草を…そのまま胃に入ります。
    ("f4.jpg", 7, 10,  False),  # ④金属は胃の壁を…集めておくんです。
    ("f5.jpg", 11, 12, False),  # ⑤一度飲んだら、一生入ったまま。
]
```

カットの境界は「前ブロック最後のカードの終了」と「次ブロック先頭カードの開始」の
中間点。これで**字幕（`s020.srt`）と映像の切り替えが、常に同じ実測データから生成される**。

#### 起きた事故と直しかた

最初のバージョンは、カットの秒数を台本の見積もり（0:00-0:03 / 0:03-0:07 / … の30秒想定）
から比例配分で決め打ちしていた。あとで字幕だけ実測（`tools/make_srt.py`）に直した結果、
**映像の切り替えタイミングだけ古いまま**になり、音声・字幕とずれた。

| カット | 見積もり比例配分（誤り） | 実測（正） | 差 |
|---|---:|---:|---:|
| f1 牛 | 2.88s | 2.39s | -0.49s |
| f2 磁石 | 3.84s | 4.65s | +0.81s |
| f3 飲み込み | 12.48s | 8.72s | **-3.76s** |
| f4 胃 | 6.72s | 10.32s | **+3.60s** |
| f5 顔アップ | 2.88s | 2.69s | -0.19s |

**③→④の境界が3.76秒もずれていた。** 「まだ飲み込みの絵なのに、もう胃の中の話をしている」
という症状はここから来ていた。

**再発防止：** 映像の尺と字幕の尺を、別々の場所で決めない。どちらも `s020.srt` という
ひとつの実測データから計算する。今後、AI音声を差し替えたら
`python3 tools/make_srt.py` → `python3 build.py` の順に**両方を作り直す**こと。
片方だけ直すと、この事故がまた起きる。

### ③だけ動かしている

12.48秒を静止画1枚で持たせるのは無理なので、**1枚の図を寄り移動させている**。
この図は「口 → 食道 → 胸」という**経路そのものを描いている**ので、
カメラがその経路をたどれば、動きがそのまま説明になる。ナレーションの2文とも一致する。

| | ナレーション | 画 |
|---|---|---|
| 前半 | 牛は草をほとんど噛まずに飲み込みます。 | 口元。草をくわえている |
| 後半 | だから牧草に混ざった針金や釘も、そのまま胃に入ります。 | 食道の釘 → 胸へ抜ける |

**ズームは1.45倍に固定し、移動だけで見せている。**
最初はズームアウトを併用したが、元画像が9:16で横に振れる余地が少ないため、
「経路をたどる」ではなく「引いていく」ようにしか見えなかった。
ズームを動かさないほうが移動が読める。

他の4カットは静止画のまま。全部動かすと落ち着かない。

## テロップを乗せる位置

生成した図は**被写体が画面中央に来ている**ため、`docs/03` の「中央よりやや上」に置くと図に重なる。
明度で被写体の占有率を測った結果：

| | 上15%（UI帯） | 中央40–62% | 下20%（UI帯） |
|---|---:|---:|---:|
| f2 磁石 | 0% | 40% | 0% |
| f3 飲み込み | 1% | 58% | 4% |
| f4 胃 | 0% | 75% | 0% |

→ **テロップは画面の 62〜78% の帯に置く。** 下20%のUI帯は避けつつ、図の下の余白を使う。

## 締めのカットについて

⑤は当初「草を食むホルスタインの横向き」だったが、**顔アップ**に差し替えた。
締めのナレーションが「一度飲んだら、一生入ったまま。」で、
正面から見つめる顔のほうが余韻が残る。

**元画像には背景に工事用クレーンが写っていた。** 寄せるほど目立つため、
クレーンの下から切り始めて外した（元画像の上21.5%を捨て、1.6倍に寄せる）。
角の先は切れるが、顔が画面を占めて締めとして強くなる。
高解像度版（1350×2400）を取り直してから切っている。低解像度のプレビューでは足りない。

テロップ（62〜78%）は鼻づらにかかる。**被写体占有率84%で背景が抜けないため、
白文字＋黒フチ3pxを必ず入れること。**

## テロップ（`s020.srt`）

CapCut の「字幕 → 字幕をインポート」で読み込む。12枚、全行12字以内。

**タイミングは推定ではなく、ナレーション音声の無音を実測して合わせている。**
`tools/make_srt.py` が `silencedetect` で発話区間を拾い、
句読点で割った文節と突き合わせている。s020 では発話区間12＝文節12で一致した。

```
python3 tools/make_srt.py <音声> <台本テキスト> [出力.srt]
```

### 読み込んだあとにやること

1. **位置を 62〜78% に下げる。** 既定の中央だと図に重なる（上の表を参照）
2. **白文字＋黒フチ3px。** ⑤の顔アップは背景が抜けないので必須
3. 強調語（台本の「強調語」列）だけアクセント黄 `#FFD60A` に変える

### 既知の限界

改行位置は句読点・助詞・活用語尾の優先順で機械的に決めている。形態素解析は入れていない。
s020 では8枚目だけ「心臓まで達することが／あります。」と割れたので手で直した。
**生成後に一度は目で確認すること。**

## 積み残し

- **③が12.48秒。静止画1枚で持たせるには長すぎる。** 実制作では2〜3カットに割る
